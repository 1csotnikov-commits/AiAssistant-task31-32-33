# Задание 33 — ассистент поддержки пользователей

## Цель

Мини-сервис на FastAPI отвечает на вопрос пользователя по FAQ/документации,
учитывая контекст тикета и пользователя, полученный через MCP CRM.

## Запуск

```powershell
aiassist support serve --host 127.0.0.1 --port 8000 --repo C:\AiAssistant --data C:\AiAssistant\demo
```

Swagger: `http://127.0.0.1:8000/docs`.

## Эндпоинты

### GET /health

Возвращает статус, версию, пути к repo/data/index и число чанков.

### POST /help

```json
{
  "ticket_id": "T-1001",
  "question": "Почему не работает авторизация?"
}
```

Логика:

1. `MCPCRMClient.get_ticket("T-1001")` запускает `aiassist mcp crm` и получает
   тикет: статус, тема, продукт, сообщения.
2. `get_user("U-001")` получает роль и тариф.
3. RAG-запрос объединяет вопрос, тему, продукт и сообщения тикета; из индекса
   берутся top-5 фрагментов `docs/faq.md` и другой документации.
4. В prompt передаются вопрос, контекст тикета, роль/тариф пользователя и
   найденные фрагменты.
5. Ответ содержит краткий ответ, что проверить, источники и MCP-строку; JSON
   дополнительно возвращает объекты `ticket` и `user`.

## Демо-тикет T-1001

- пользователь `U-001`, роль `viewer`, тариф `basic`;
- тема «Не работает авторизация»;
- сообщение «Пользователь не может войти после смены роли».

FAQ говорит: SSO доступен только роли `admin`, а тариф `basic` не включает SSO.
Правильный ответ ассистента:

1. проверить роль пользователя — `viewer` не имеет доступа к SSO;
2. проверить тариф — для SSO нужен `enterprise`;
3. попросить администратора изменить роль/тариф и повторно войти;
4. не утверждать, что «упал сервер», пока роль и статус не проверены.

## MCP CRM

```powershell
aiassist mcp crm --data C:\AiAssistant\demo
```

Инструменты: `get_ticket(ticket_id)`, `get_user(user_id)`,
`list_user_tickets(user_id)`. Данные — синтетические `demo/tickets.json` и
`demo/users.json`.

## Тестирование

`tests/test_support.py` использует `TestClient`, fake LLM и fake CRM, поэтому
тесты не требуют сети, ключа и запущенного MCP-сервера. Проверяются:

- `/health` возвращает `status=ok`;
- `/help` учитывает роль `viewer` и возвращает источник из FAQ;
- 404 для неизвестного тикета;
- отсутствие выдуманного ответа при пустом индексе.

## Ограничения

- Нет аутентификации и реальной CRM.
- Сервис синхронный: MCP-вызов выполняется в threadpool FastAPI.
- Ответ зависит от качества FAQ; при отсутствии раздела возвращается
  «В документации этого нет».
